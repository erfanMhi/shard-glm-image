# shard-glm-image

Docker image and launcher that reproduce leyten/shard's GLM-5.2 WAN run (receipt `glm52-nvfp4-wan-20260618`, 30.03 tok/s): 6 stages x 13 NVFP4 layers on RTX PRO 6000 plus a coordinator with a CUDA-graphed GLM-4-9B draft. Runtime pinned to shard fcf7280's `requirements_vmoe.txt` (vllm 0.23.0, torch 2.11.0 cu13, transformers 5.12.1) in `/root/vmoe`. `NOTES.md` has the diffs, the wheel check, and what surprised us in shard's scripts.

- **Build**: push to `main` (or Actions > build > run). Publishes `ghcr.io/erfanmhi/shard-glm:cu13-vllm0.23` and `:<short sha>`. Base is `vastai/base-image:cuda-13.2.1-auto`, so vast hosts already cache most layers.
- **Rent**: `vastai create instance <OFFER> --image ghcr.io/erfanmhi/shard-glm:cu13-vllm0.23 --disk 150 --ssh --direct --env '-p 29600:29600' --label erfan-glm-<state>`. Add `-p 29601:29601` if you want iperf3 while stages hold 29600.
- **Smoke test one box first**: `ssh -p <port> root@<ip> 'HF_TOKEN=... bash /root/smoke_test.sh 2>&1 | tee /root/smoke.log'` (versions, profile, layer-6 fetch, draft compat, draft bench, NVFP4 MoE on real weights, loopback stage probe; ~25 GB download, ~20 min).
- **Profile a box**: `bash /root/profile_box.sh` writes `/root/profile.json`. Edge throughput: `bash /root/iperf_edge.sh --server 29600` on B, then `bash /root/iperf_edge.sh <B ip> <B mapped port>` on A.
- **Run the ring from the Mac**: `python3 scripts/launch_ring.py --ids <7 ids> --coord-id <id> --mode cg --runs 3 --trace --out runs/cg` (waits for boxes, checks the venv, measures the RTT mesh, solves the ring order, fetches weights in parallel, launches stages, runs the coordinator 3 times, pulls stdout/dumps/traces). `HF_TOKEN` in the environment is forwarded to the fetch.
- **Per-role commands the launcher issues** (cwd `/root`, `python` = `/root/vmoe/bin/python`):
  - stage: `python glm_swarm_nvfp4_kv.py stage --layers 0 1 ... 12 --port 29600 --next <ip:port> [--ring]`; tail's `--next` is the coordinator's `ip:mapped 29600` in ring modes, absent in relay modes.
  - coordinator, ladder rung by rung: `plain` = `glm_swarm_nvfp4_kv.py coord --stage HEAD` (1.87) | `relay6` = `glm_swarm_nvfp4_draft.py coord --stage HEAD --K 6` (1.99) | `direct6` = same `--ret-port 29600` (2.94) | `pipe` = `glm_swarm_nvfp4_pipe.py coord --stage HEAD --ret-port 29600 --depth 6 --K 2` (16.6) | `cg` = `glm_swarm_nvfp4_cg.py coord --stage HEAD --ret-port 29600 --depth 6 --K 2 --compile --dump run.json` (30.03). Extras: `cgeager` (cg without `--compile`, the receipt's reference) and `cgplain` (`cg.py --plain`, 1-token greedy over the ring with a dump).
  - all with `--prompt "def quicksort(arr):" --max-new 96`. Stages are restarted only when the mode class changes (relay: plain, relay6; ring: everything else).
- **Traces**: `--trace` sets `STAGE_TRACE=/root/stage_trace.jsonl` on stages (one JSON line per message: `sp, ntok, t_wait0, t_recv0, t_recv1, t_comp1, t_send1`) and `COORD_TRACE` on the coordinator (one line per chunk: `send_pos, K, t_draft0, t_draft1, t_send, t_wait0, t_recv, verdict`, then a summary line). Unset means byte-for-byte the original behavior.
- **Receipt check**: `cg`/`cgeager`/`cgplain` dumps are hashed (`sha256(json.dumps(output_token_ids))`) and compared with the receipt's `d9e61275...`; `manifest.json` records `matches_receipt` per run.
- **Teardown**: copy `runs/<out>/` to the wiki's `raw/experiments/`, verify, then `vastai destroy instance <id>` for every `erfan-glm-*` id only, and confirm with `vastai show instances`.
